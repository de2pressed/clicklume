# October 2026 audit: runtime, IPC, settings, and installation

Audit date: 2026-10-03. These fixes preserve passive evdev reads, unprivileged
runtime, user systemd services, and the required REL_X/REL_Y declaration.

## Confirmed defects and fixes

- F11/F12 were mapped as contiguous F1..F10 codes. Their actual evdev codes are
  now handled separately and covered by a regression test.
- Physical F8 decrease subtracted an extra CPS; hotkeys and IPC now share the
  same atomic rate update and honor configured minimum/maximum CPS bounds.
- Focused GUI fallback could race physical hotkeys and toggle twice. Backend
  subscriptions now report `HotkeyAvailability(bool)`; the GUI uses fallback
  only when no physical reader is registered.
- Backend assumed one socket read contained a whole command. Reads now
  accumulate incomplete JSON with size/time limits; replies are validated by
  GUI/CLI clients. CLI failure to receive a valid Status is nonzero.
- Backend startups could unlink an existing backend's live socket. A per-user
  lifetime flock serializes startup, with a live-socket check for old versions.
  GUI/CLI clients no longer unlink backend-owned sockets.
- IPC socket was world writable. It is now created with restrictive umask and
  mode 0600. GUI pushes have bounded write timeouts, and subscription cleanup
  checks socket identity before clearing a potentially newer subscription.
- uinput creation could fail silently inside a detached worker while IPC looked
  healthy. Creation now completes before startup succeeds; emission failures
  disable clicking and notify the GUI. Shutdown joins the click worker, and
  button-hold waits observe Stop/Quit every 2ms.
- Hotplug monitor deliberately leaked JoinHandles with `mem::forget`; detached
  handles are now dropped normally.
- Queued GUI snapshots could overwrite newer global-hotkey settings. Saves
  stage current state synchronously, merge only changed GUI fields, and debounce
  writes of the latest state. GUI exit flushes staged preferences.
- Config/state writes could truncate TOML on a crash. Existing settings writers
  now use same-directory temporary files and atomic rename.
- Saving only hotkeys into a fresh config left required backend fields absent.
  Partial configs now inherit Config defaults.
- GUI controls/restoration capped CPS at 100 despite the 1000 backend limit.
  Their ranges now match. Rate is a target, not a measured delivery guarantee;
  repeat count counts actions, with two clicks per double action. Hold mode
  now holds for the full configured interval as documented.
- Failed source builds could install stale binaries. Installer now stops on
  required failures, preserves existing login-start enablement, and allows
  interactive sudo only during one-time system setup.
- A priority-99 uinput rule adds its tag after Ubuntu's 73-seat-late ACL rule.
  It now explicitly schedules the `uaccess` builtin. Installer and Debian
  postinst refresh misc/uinput as well as input devices.
- Opening GUI silently rewrote service enablement from possibly stale state.
  Startup now reads actual service enablement; failed checkbox changes show an
  error and preserve the previous value.
- GUI self-pipe was inherited by backend exec and intentionally leaked its read
  descriptor. The pipe is now CLOEXEC and the reader closes normally.

## Verification entry points

- `cargo test --workspace --locked`
- `cargo clippy --workspace --all-targets --locked -- -D warnings`
- `cargo fmt --all -- --check`
- `cargo build --workspace --release --locked`
- `python3 tests/install-regression.py` (mocked installer; no system mutation)
- `python3 tests/live-smoke.py` (application must be closed; temporary config;
  release binaries by default; no emitted clicks or physical hotkeys)

Live smoke checks command fragmentation, subscriptions and health probes,
configured CPS bounds, duplicate startup, socket permissions, virtual-mouse
REL capabilities, backend Quit, native GUI launch, backend SIGKILL recovery,
GUI-owned IPC Quit recovery, and graceful GUI termination. Actual delivered
click rates, real physical-key presses, and fresh-machine udev activation
require separate interactive verification. System permission files are not
installed by the audit.
